# Нативные программы CAT (.exe для Windows, Mach-O для macOS Intel, ELF для Linux)

```
python -m catlang exe prog.cat --target windows   # -> prog.exe   (Windows x64)
python -m catlang exe prog.cat --target macos     # -> prog       (macOS, процессор Intel x86-64)
python -m catlang exe prog.cat --target linux     # -> prog       (Linux x86-64)
python -m catlang exe prog.cat --seed 5           # зафиксировать начальное число для roll() (иначе — от времени)
```
Без `--target` собирается для той системы, на которой запущен компилятор. Файл **самодостаточный**: ни Python,
ни библиотек CAT на целевой машине не нужно (на Windows используется только системная `kernel32.dll`).
Компилировать можно на любой системе — для Windows-файла Windows не нужен.

## Что поддерживается (v1)
Числа всех типов, `bool`, функции и рекурсия, `sniff/hiss`, `chase`, `prowl`, `scat/hop`, `&&`/`||`, все операции
`C A T S`, печать (`meow`/`mew` для чисел, `bool`, строковых литералов), `ask`/`heard`, `roll`, `claw`, `look*`/`bat*`,
модуль `math`. Ошибки выполнения (деление на 0, сдвиг, `claw`, выход за память, конец ввода) — сообщение в stderr и
код выхода 3, как в виртуальной машине.
**Пока нет** (понятная ошибка при сборке): массивы, строки-значения, структуры, `bury`, `listen` — куча для
нативных программ будет следующим шагом. Для них доступны VM и WebAssembly.

## Как устроено
* `catlang/native/asm.py` — свой ассемблер x86-64 (кодирование команд вручную; сверено с `objdump`).
* `catlang/native/codegen.py` — дерево программы → машинный код. Каждое значение — 64-битное число в `rax`
  (знаковые расширены знаком, беззнаковые нулём), после операций приводится к своему типу; промежуточные значения —
  в стеке; локальные — `[rbp-8*(слот+1)]`; `r15` — адрес памяти программы.
* `stdlib/rt.cat` — **рантайм на самом CAT**: печать чисел, чтение и разбор ввода, `roll` (xorshift64, тот же, что в VM).
  Он опирается на три системных вызова (`__write`, `__read`, `__exit`) и `__trap`; это единственное, что отличается по ОС.
* `catlang/native/platform.py` — эти вызовы: Linux/macOS — `syscall` ядра; Windows — `GetStdHandle`, `WriteFile`,
  `ReadFile`, `ExitProcess` из `kernel32.dll` (+ `SetConsoleOutputCP/CP(65001)`, чтобы русский текст в консоли не ломался).
* `catlang/native/formats.py` — записывает файлы: ELF64, PE32+ (таблица импорта kernel32), Mach-O (статический,
  `LC_UNIXTHREAD`, без динамического компоновщика).

## Что проверено, а что — нет
* **Linux (ELF)**: файлы запускаются по-настоящему; результат сверяется с виртуальной машиной на всех операциях ×
  всех типах, приведениях, циклах, разборе ввода, `roll`, ловушках, рекурсии на 10 000 уровней (`tests/test_native.py`).
* **Windows (PE) и macOS (Mach-O)**: машинный код тот же; файлы разбираются сторонними библиотеками (`pefile`,
  `macholib`, `llvm-objdump`), раскладываются в память эмулятора процессора по таблицам самого файла и выполняются с
  теми же сверками (`tests/test_native_emul.py`; для Windows дополнительно проверяется выравнивание стека на вызове API).
* **Не проверено на настоящих Windows и Mac.** Эмулятор не повторяет загрузчик ОС: возможны отказы вида «файл не
  запускается» из-за мелочей заголовка. Если так — пришли точное сообщение системы, поправлю.

## Как проверить у себя
**Windows (PowerShell):** `python -m catlang exe examples\hello.cat` → `.\examples\hello.exe`.
SmartScreen может предупредить о «неизвестном издателе» (файл не подписан) — «Подробнее → Выполнить в любом случае».
**macOS Intel (Terminal):** `python3 -m catlang exe examples/hello.cat` → `./examples/hello`.
Если система блокирует файл: `xattr -d com.apple.quarantine examples/hello` (если он скачан) или
`codesign -s - examples/hello` (подпись «ad hoc»). Для Mac на Apple Silicon (ARM) эта сборка не подходит (другой процессор).

## Риски и ограничения
* Mach-O собран по спецификации и проверен разборщиками, но как настоящий загрузчик macOS его не принимал; статические
  файлы без `dyld` — поддерживаемый, но редкий путь; на новых версиях macOS возможны дополнительные требования.
* Системные вызовы macOS напрямую (без libSystem) — допустимы, но Apple их официально не гарантирует; запасной план —
  вызывать функции libSystem через динамическую загрузку.
* Нет защиты от `DEP/ASLR`-проблем на Windows: образ грузится по фиксированному адресу `0x140000000` без таблицы
  перемещений; код позиционно-независим, так что включение ASLR — небольшая доработка.
* Оптимизации кода нет (простая схема «всё через `rax` и стек»): быстрее VM в разы, но далеко от Go/Rust.
  Распределение регистров и оптимизатор — следующий этап.
